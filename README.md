# Crowdstalking_agents

A map-based location intelligence and crowd-monitoring platform: draw a polygon to see
what's inside it (streets/shops), simulate a city's live population, detect crowd
anomalies (panic/riots) from that telemetry with plain statistics, and react to detected
incidents with an agentic pipeline.

Everything runs locally/offline except the explicitly wired free-tier APIs (Nominatim,
Reddit, Google Custom Search, Groq). **Every outward "action" tool is mocked** — nothing
places a real call, sends a real email/SMS, or posts anywhere real.

Further docs: [`ARCHITECTURE.md`](ARCHITECTURE.md) (how the pieces connect),
[`DECISIONS.md`](DECISIONS.md) (why things are built this way),
[`PROGRESS.md`](PROGRESS.md) (what's done / next).

## Components

| Folder | Language | Purpose |
|---|---|---|
| `map-app/` | Node/Express | Map UI (MapLibre GL), polygon drawing, city search, "Live" device overlay, "Citizen.AI" incident panel |
| `osm-extract/` | Python | `extract.py` — polygon → streets/shops lookup over an OSM extract |
| `simulation/` | Python | `live_position_simulator.py` — simulates N devices as a city's population |
| `social-media-sentiment-agent/` | Python | `crowd_anomaly_agent.py` — the crowd-anomaly detector (not social-media based; folder name is legacy) |
| `crowd-monitoring-agent/` | Python | Agentic response pipeline: context gathering → live intelligence search → mocked dispatch |
| `cases/` | Python | Scenario studies and their rendered reports/snapshots |

## Data flow

`live_position_simulator.py` → `live_positions.json` → `crowd_anomaly_agent.py` →
`crowd_risk.json` → (`map-app`'s Citizen.AI panel, manual) **and**
(`crowd-monitoring-agent/poller.py`, automatic) → `crowd_monitoring_output.json`.

## Data not in this repo

Large source and generated data is gitignored (~1.2 GB; several files exceed GitHub's
100 MB limit). Recreate it as follows.

**1. OSM extracts** — `osm-extract/data/*.osm.pbf`

Download the regional extracts named in [`osm-extract/regions.json`](osm-extract/regions.json)
(`Frankfurt.osm.pbf`, `Berlin.osm.pbf`) from a provider such as
[Geofabrik](https://download.geofabrik.de/) or [BBBike](https://download.bbbike.org/osm/)
and place them in `osm-extract/data/`.

**2. Street/place indexes** — `osm-extract/data/*.index.json`

Built once per city from the `.pbf`:

```bash
cd osm-extract
python3 -I extract.py --pbf data/Frankfurt.osm.pbf --build-index data/Frankfurt.index.json
python3 -I extract.py --pbf data/Berlin.osm.pbf    --build-index data/Berlin.index.json
```

**3. Synthetic population datasets** — `simulation/*.csv`

```bash
cd simulation
python3 -I generate_synthetic_subscribers.py
python3 -I generate_location_pings.py
```

Runtime output (`live_positions.json`, `crowd_risk.json`, `crowd_monitoring_output.json`,
`*.log`) is regenerated by simply running the pipeline, and is also gitignored.

## Setup

```bash
# Python deps
pip install -r crowd-monitoring-agent/requirements.txt

# Node deps for the map UI
cd map-app && npm install

# API keys (all optional; stage 1 of the response pipeline needs none)
cp crowd-monitoring-agent/.env.example crowd-monitoring-agent/.env
# then fill in the values -- see .env.example for where each free-tier key comes from
```

## Running

Four terminals:

```bash
# 1. simulate a city (10k devices, normal traffic + a forced incident for testing)
cd simulation && python3 -I live_position_simulator.py --devices 10000 --tick 2 \
  --force-protests 1 --force-protest-at 8 --force-protest-radius-km 4.2

# 2. the detector
cd social-media-sentiment-agent && python3 -I crowd_anomaly_agent.py

# 3. the map UI -> http://localhost:3000
cd map-app && node server.js

# 4. the agentic response pipeline
cd crowd-monitoring-agent && python3 -I poller.py
```
